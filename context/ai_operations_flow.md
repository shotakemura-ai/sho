# 24 時間 AI 運用フロー

> 「**自分が寝てる時間も、移動中も、会議中も、AI が動き続けている状態**」を作る。
> あなたの役割は2つだけ：**発注（dispatch）と検収（review）**。
> 作成日：2026/06/09 ／ **v2 再設計：2026/06/10**

---

## 🎯 全体の思想（30秒で）

| 旧モデル | 新モデル |
|----------|----------|
| AI = アシスタント（呼んだら来る） | AI = **24時間動く外部チーム** |
| 自分が動いている時だけ AI も動く | 自分が寝てる時こそ AI が稼ぐ |
| AI に質問する | AI に**発注**する |
| 結果を待つ | 結果がスマホに**通知される** |
| 1度に1タスク | **5〜10タスク並列** |

---

## 🏗️ 3層アーキテクチャ（v2 の核心）

「24時間動く」を実現する3つの層。上に行くほど人間の関与が減る。

| 層 | 名前 | 動き方 | 人間の役割 |
|----|------|--------|------------|
| **L1** | 手動発注 | スマホ / PC から発注 → クラウドセッションが実行 | 発注と検収 |
| **L2** | バンドル発注 | 「**B-001**」の一言で、1セッション内に**複数エージェントが並列起動** | 一言発注と検収 |
| **L3** | 完全自動 | **GitHub Actions が定時に勝手に起動**（毎朝のブリーフ、週次振り返り） | 検収のみ。発注すら不要 |

### v2 で変わったこと（重要）

1. **クラウドでも Asana / Gmail / カレンダー / Slack / Drive が使える**（MCP 接続済み）。
   「Asana は Windows 専用」は**過去のルール**。今はスマホ発注のクラウドセッションから直接 Gmail 要約も Asana サマリーもできる。
   Windows 必須なのは**社内ネットワークドライブと経費精算スクリプトだけ**。
2. **タブを10個開かなくていい**。バンドル発注（B-XXX）なら1つのセッションが内部で並列エージェントを起動する。
   スマホ操作は「1メッセージ」で済む。
3. **クラウドセッションはアプリを閉じても動き続ける**。発注 → ポケットにしまう → 通知で受け取る。
4. **L3 は発注ゼロ**。寝てても出張中でも、毎朝のブリーフは GitHub Actions が生成して repo に commit する。

## 📦 バンドル発注（B-XXX）— 一言で複数 AI を起動

スマホから「**B-001**」とだけ送れば、Claude が中身を展開して並列実行する。
（各 B は下の「タスクパック」を1メッセージ化したもの。Claude はこの定義を読んで忠実に展開すること）

| ID | 名前 | 中身（並列実行） | 使う時 |
|----|------|------------------|--------|
| **B-001** | 朝パック | T-205 業界ニュース + T-202 Gmail 未返信 + T-201 Asana サマリー + 今日のカレンダー確認 | 起床後・通勤中 |
| **B-002** | 夜パック | T-004 鉄鋼市況 + T-205 ニュース + 明朝ブリーフ用調査 + ops_log 追記 | 寝る前 |
| **B-101** | 缶バッジ週次 | T-101 + T-102 + T-103 をまとめて | 週1 |
| **B-301** | 副業週末 | T-301 + T-302 + T-303 + T-305 をまとめて | 週末 |
| **B-401** | 家計月初 | T-401 + T-402（+ 必要なら T-405） | 月初 |
| **B-901** | 週次振り返り | learnings.md 追記 + ops_log 集計 + 来週の優先順位提案 | 日曜夜（L3 で自動化済み） |

**発注例（スマホから1行）**：
```
B-002。出力はいつもの場所。終わったら ops_log に記録して。
```

## 🤖 L3：完全自動レイヤー（GitHub Actions）

`.github/workflows/` に定義済み。**発注不要、勝手に動く**。

| ワークフロー | スケジュール | やること |
|--------------|--------------|----------|
| `morning-brief.yml` | 毎朝 05:30 JST | Web 調査 → `鉄鋼事業部/マーケティング/morning_brief_YYYYMMDD.md` を生成して main に commit |
| `weekly-review.yml` | 日曜 21:00 JST | ops_log と今週のコミットを集計 → learnings.md に週次振り返りを追記して commit |

- **初回セットアップ（1回だけ・5分）**：GitHub の repo Settings → Secrets and variables → Actions → `ANTHROPIC_API_KEY` を登録
- 手動で今すぐ動かす：GitHub の Actions タブ → ワークフロー選択 → 「Run workflow」
- 制約：Actions 内は Web 調査 + repo 操作のみ（Gmail / Asana 等の MCP は使えない。それは L1/L2 の仕事）

## ⏰ 1 日のリズム（実装例）

### 🌅 05:30 起床5分前
**iPhone に通知が鳴る**：前夜発注した朝のブリーフィング完成
- 鉄鋼市況 / 業界ニュース / Gmail 未返信 / Asana 朝サマリー

布団の中で読む。これだけで本日の戦況がインプット完了。

### 🚃 07:00 通勤中
スマホから音声 or テキストで2〜3件発注：
- 「**T-202 Gmail 未返信を要約**」
- 「**T-201 今日着手すべき Asana タスクを優先順位付きで**」
- 「**今日訪問する○○商事の最新ニュースを 3 つ調べて**」

電車を降りる頃には、デスクで読む資料が揃ってる。

### 🏢 09:00 出社直後（15分）
朝のレビュー：
- 通勤中の発注結果 → 採用 / 再発注 / 不採用に仕分け
- 学びを `learnings.md` に1〜2行追記
- 今日のメイン発注（午前バッチ）を投げる

### 💼 12:30 ランチ前
午前の結果を確認しつつ、午後バッチを発注：
- 商談前の準備（T-002 提案書下書き）
- 顧客向けメール案（T-003）

### 🚗 17:00 退社前
**明日朝のブリーフィングを発注**：
> 「明日 6/10 朝のブリーフィング、T-004 + T-205 で morning_brief_20260610.md に保存」

これで明朝の自分への贈り物が予約完了。

### 🍷 21:00 寝る前
**並列発注タイム（最重要）**：iPhone でタブを5〜10個開いて一気に発注。
- 鉄鋼マーケットの深掘り調査
- 副業の楽曲コンセプト案出し
- SNS 投稿7本の起案
- 家計の月次収支まとめ
- 業界レポートのリサーチ

寝る。

### 🌅 翌朝
通知5〜10件。**朝のコーヒー10分でレビュー → 採用**。
→ また 1 日のリズムが回る。

## 📱 iPhone での操作（実装ガイド）

### ホーム画面
- **Claude アプリをドック**（4 アプリの 1 つに昇格）
- ショートカットアプリで「**いつものお願い**」音声ショートカット作成

### 並列起動の手順（v2：まずバンドル、足りなければタブ）
1. Claude アプリ / claude.ai/code で新規セッション
2. 「**B-002**」のように一言発注 → セッション内で並列エージェントが起動
3. アプリを閉じて OK（クラウドで動き続ける）
4. 別系統のタスクがある時だけ、新規セッションを追加で開く

→ 旧方式（タブ10個）も使えるが、**B-XXX 1発の方が速い**。タブを分けるのは「系統が違うタスク」の時だけ

### 音声で発注（運転中・歩行中）
- Siri 経由 or Claude アプリの音声入力
- 「**T-205 を今やって**」だけで通る
- 結果はテキストで返ってくる

### プッシュ通知
- Claude アプリの通知を**全許可**
- 完了通知で結果がプレビュー
- 重要度低い結果は朝まとめて確認 OK

## 🚦 結果のハンドリング（レベル別）

| レベル | 例 | 対応 |
|--------|----|----|
| **A. 即採用** | 業界ニュース要約、Suno プロンプト、SNS 投稿案 | 採用してそのまま使う or 軽く修正 |
| **B. 一読して確認** | 提案書下書き、メール下書き、楽曲コンセプト | 内容チェック → 微修正 → 使う |
| **C. 必ず人間判断** | 見積金額、契約条件、人事関連、顧客への送信、税務 | AI は叩き台、判断は本人 |
| **D. 不採用** | ピンとこない、的外れ | フィードバックを `learnings.md` に1行残す |

---

## 🚫 自動化してはいけないこと

1. **金額・納期の確約**（必ず人間最終判断）
2. **顧客への直接送信**（メール下書きは AI でも送信は人間）
3. **採用判断**
4. **倉元君のような繊細な対応**（メンタル・健康関連）
5. **税務判断**
6. **大型支出の決定**
7. **重要顧客への一次対応**（クレーム対応含む）

## 🎬 まとめ：あなたの 1 日 vs AI の 1 日

```
あなたの24時間
00-06  睡眠
06-09  起床・通勤
09-17  本業
17-21  家族・食事
21-23  寝る前 → 並列発注
23-00  睡眠

AI の24時間（あなたの代わりに動く時間）
00-06  寝てる間に深夜バッチ完了
06-09  通勤中の調査・要約
09-17  会議中も並列でリサーチ・下書き
17-21  退社後も発注済み案件が進行
21-23  並列発注で大量投入
23-00  深夜バッチ稼働開始

→ AI に発注している時間：1日あたり30〜60分
→ AI が代わりに働いてくれている時間：1日あたり10〜20時間
```

これが「24時間 AI に仕事を任せる」の正体です。
