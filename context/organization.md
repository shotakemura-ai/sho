# 運用ルール

## 大前提：Claude は1人

窓口（ブラウザ / Windows Desktop）に関わらず、Claude は1人。
役割や人格を切り替える必要はなく、常に同じ Claude として動作する。

詳細は `context/assistant.md` 参照。

---

## 窓口（覚えることはない）

iPhone・会社 PC・Mac、どの端末のどの窓口（ブラウザ / Claude アプリ / Claude Code Desktop）から
開いても、**同じ1つの仕組み**につながる。Asana / Gmail / カレンダーもクラウド MCP で使える。

**端末に役割を割り当てない。**「Mac はプライベート」「Windows は仕事」という使い分けは廃止
（考えること自体が効率化の阻害要因）。仕事も個人も、そのとき手近な画面でやる。
文脈（仕事か個人か）の判別は Claude の仕事。

唯一の例外は物理的制約：**社内ネットワークドライブと経費精算スクリプトは会社の Windows からのみ**。
当たったら Claude がその時だけ「これは会社 PC で」と案内する。

---

## 起動ワード（全窓口共通）

```
いつものお願い。
```

これを送れば Claude が `git pull` → 必要な context を読み込み → 環境を自己診断 → 「準備完了」を返す。

---

## 共通ルール

1. セッション開始時に必ず `git pull origin main` で最新化する
2. `CLAUDE.md` や `context/*` を変更したら必ず `git commit & push` する
3. 重要な資料は git にコミットして全窓口で共有する
4. 環境に依存する情報（トークン等）は `context/.secrets` に置き、git 管理外にする

## 古いルールが出てきた時の直し方（トラブルシューティング）

Claude が「このPCは本業専用」「Mac は個人用」など**廃止済みの端末役割ルール**を口にしたら、
その Claude は古いローカル記憶を読んでいる。repo は正しい。その場で以下を指示すれば直る：

> そのルールは廃止済み。①`git pull origin main` で最新化 ②端末役割ルールがローカルに残っていないか探して削除
> （このフォルダの CLAUDE.md / CLAUDE.local.md / ユーザーメモリ `~/.claude/CLAUDE.md` / `.claude/` 配下）
> ③正しいルールは organization.md 参照：端末に役割なし。仕事/個人の判別は話題から Claude が行う。
> 例外は物理制約2件のみ（社内ネットワークドライブ・経費精算）④掃除したら commit & push

**Claude への指示**：この repo 以外の場所（別クローン・ユーザーメモリ・ローカル設定）に
独自ルールを書かない。全ルールはこの repo に一元化する。ローカルに書くと窓ごとに人格が割れる。
