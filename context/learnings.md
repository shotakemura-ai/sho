## 2026-05-28 セッションで確定した運用ノウハウ

### [認知負荷] 「Claude は1人」モデルへの収斂
- **状況**：Windows / Mac / クラウドの3マネージャー定義 + private repo 分離案など、構造を増やすほど竹村が混乱
- **試したこと**：段階的に「マネージャー概念を削除」「private repo 計画を撤回」「1 repo に統合」
- **結果**：起動ワード「いつものお願い。」1つで全窓口共通、財布も1つに
- **学び**：「分けて整理する」と「シンプルにする」は逆向き。中小企業オーナー1人運用なら**統合が正解**

### [セキュリティ] git に約 17 MB の機密データが混入していた
- **状況**：財務管理表・販売実績 CSV・経費精算 xlsx 等が repo にコミット済
- **試したこと**：`dev_rules.md` で「機密データを repo に置かない」と宣言しつつ実態と矛盾していた
- **対応**：8 ファイルを `git rm`、`.gitignore` でフォルダ単位ブロック、Drive で別管理
- **学び**：**ルールを書く時は repo の実態と同時にチェックする**。宣言と実態が乖離すると意味がない

### [経費精算] 接待ゴルフの「割り勘」は分類判断が必要
- **状況**：取引先と4名でゴルフ、当社2名分のみレシートに反映（先方は自費）
- **学び**：「接待した（先方を負担）」と「懇親で割り勘した」は税務処理が変わる可能性あり。最終的な勘定科目判断は経理（または税理士）に投げるのが正解

### [ツール比較] Microsoft Copilot < Claude / ChatGPT（再確認）
- 三幸商事は Microsoft 365 + Azure 導入済みだが、Outlook / Teams を使っていない
- そのため Microsoft の「Work IQ」優位は無効化されている
- 真の社内文脈は **Asana** にある（Asana ↔ Claude 連携が最重要投資）

### [経営者マスタリー] Lv.3 → Lv.5 への道
- 1日で「タスクテンプレ整備」「並列実行運用」「機密データ衛生」「アプリ開発ルール」までやり切った
- 中小企業オーナー上位 1% の AI 活用レベルに到達
- ただし**社内展開はまだ早い**。自分が Lv.5（戦略家）になるまでは個人マスタリーを優先

## 2026-07-06 [失敗→再設計] v2 は設計2日・稼働0日で停止 → v3「ゼロ記憶」へ

- **状況**：6/10 に v2（3層アーキ・T-XXX 30本・B-XXX 6本・Routine 5本・KPI 週30〜50件）を構築 → 6/11〜7/5 の26日間、発注ゼロ・コミットゼロ・Routine 成果物ゼロ
- **学び**：**覚える運用は続かない**。人間起点の習慣設計は忙しい営業部長には不成立。記録義務と件数 KPI は罪悪感を生んで逆効果。仕組みは「AI 起点・記録は AI・覚えるのは1語」に倒すしかない
- **対応**：v3 再構築。コード全廃（日本語で依頼）、Routine は R-daily 1本から、記録は Claude の仕事、KPI は「浮いた時間はあったか？」の1問のみ、増築禁止ルール導入
- **併せて**：端末（iPhone / 会社PC / Mac）は「窓」であり仕組みは repo + クラウドの1つ、を明文化（一元化）。さらに「Mac=プライベート／Windows=仕事」の役割割り当ても全廃 — 使い分けを考えること自体が阻害要因。残る制約は物理の2件（社内ドライブ・経費精算）のみ

## これまでに確定している前提（戦略レベルの学び）

### 2026-05 [ツール比較] Microsoft Copilot は期待外れ
- **状況**: Microsoft 365 と Azure を導入済みで、Copilot も試用した
- **試したこと**: Copilot を業務メール作成・文書要約などに使用
- **結果**: Claude / ChatGPT に体感品質で大きく劣ると判断
- **学び**: 三幸商事の AI 投資は **Claude を中核**に据える。Copilot は契約解除候補。

### 2026-05 [戦略] Microsoft の「データ統合」優位は無効
- **状況**: 365 を入れているが、Outlook / Teams は未使用
- **学び**: Microsoft AI が宣伝する「Work IQ（社内メール・チャットの文脈理解）」は、データ源が Microsoft 側に存在しないため三幸商事には適用不可。Azure はインフラ用途のみで利用継続。

### 2026-05 [戦略] 真の社内文脈は Asana にある
- **状況**: 社内コミュニケーションは Asana で完結
- **学び**: AI に読み込ませるべき「社内の文脈データ」は Asana が中心。クラウド（Google / Microsoft / AWS）の選定は AI 品質を決めない。**Asana ↔ Claude 連携の深化が最重要投資**。

### 2026-05 [戦略] 経営者の個人マスタリーを優先
- **学び**: 社内展開より先に、まず社長自身が Claude を Lv.5（戦略家レベル）まで使いこなす。これが中小企業 AI 導入の唯一の正解。模範を示すことが最強の社内展開戦略。

### 2026-05 [並列実行] Boris の「数千体並列」モデル
- **学び**: スマホ + Claude Code on the web で誰でも実践可能。三幸商事版は「寝る前に複数タスクを発注、朝にスマホで通知確認」。`context/task_templates.md` をタスク辞書として活用。
