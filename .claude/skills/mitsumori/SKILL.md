# /mitsumori — 見積・回答の一気通貫（数字は「案」まで。決めるのは翔さん）

らすく式「完成品で出す」を、鉄鋼商社のクリティカル7（金額・納期の確約）と両立させる設計。
**Claude は「参考値＋案＋検問済み」まで作る。単価・納期の確定と送信は翔さん。**
起案班（作る）→ 検算班（疑う）→ 翔さん（決める）の順を崩さない。

## 0. 準備
1. `TZ=Asia/Tokyo date '+%Y-%m-%d (%a)'` で今日を確定
2. context/me.md・context/preferences.md・context/email_context.md・`鉄鋼事業部/営業/CLAUDE.md`（見積ルール：必須記載・有効期限30日・初回は上下10%の幅）・context/customers.md を読む
3. 文脈を判定：**鉄鋼**（ブリキ・鋼板・コイル・海外ミル。単価は円/kg か円/t）か **缶バッジ**（キャラバン等の OEM・セット単価×枚数・仕様パターン・送料・校正・リードタイム）か

## 1. 問い合わせを特定して「要求仕様」にする
- 入力元（上から順）：貼られた本文 → Gmail を会社名・件名で過去7日検索（該当スレッドを開く）→ Asana（キャラバン受注管理など）の該当タスク → 無ければ「どの問い合わせですか？」と1回だけ聞く
- 要求仕様の表を作る（埋まらない欄は**空欄のまま「先方に確認」**。推測で埋めない）

| 項目 | 内容 | 出典 |
|---|---|---|
| 相手先・担当者 | | |
| 品目・規格（材質・寸法・仕様／缶バッジならサイズ・種類数・枚数・仕様パターン） | | |
| 数量（単位を明記：t／kg／枚／セット） | | |
| 希望納期・納入場所 | | |
| 支払条件・その他条件 | | |
| 回答期限 | | |
| 新規／リピート／変更 | | |

- **回答期限が今日〜明日なら、報告の1行目にそれを書く**

## 2. 参考価格と条件を集める（社内だけ。調査班は使わない＝顧客情報を外に出さない）
| どこ | 何を | 取り方 |
|---|---|---|
| Gmail | 同じ相手・同じ品目の過去見積／回答（12ヶ月） | 会社名＋「見積」「御見積」「単価」で検索。日付・件名・数字を控える |
| Asana | 同じ品番・仕様の過去案件 | キャラバン受注管理などで品番・IP名・仕様語で検索。前回の単価・納期・数量 |
| `鉄鋼事業部/営業/見積書/`・`缶バッジ事業部/営業/` | 過去の見積ファイル | 会社名・品目で grep |
| `context/customers.md` | 取引条件・備考 | 会社名で grep |
| `経営企画室/レポート/判断キュー/判断キュー_最新.md` | 同案件が🔴🟠に載っていないか | 載っていれば「判断キューの指摘」を引き継ぐ |

- 見つかった数字は**必ず出典付き**で控える（例：`2026-07-03 メール「呪術 缶バッジセット 御見積」／2,050セット＠¥xxx`）
- リピートなら「前回条件」を最優先で並べる
- **仕入価格・原価・粗利は、見つけても社外向け文書には一切書かない**（社内報告にも「参考（社外秘）」と明示して分ける）

## 3. 叩き台を作る（起案班 `kian-han` に Agent で委託）
渡すもの：要求仕様の表、参考価格（出典付き）、テンプレのパス、文脈（鉄鋼／缶バッジ）、email_context.md の型
作らせるもの：
- **鉄鋼**：`鉄鋼事業部/営業/見積書/templates/見積書_テンプレート.md` に沿った見積書ドラフト（振込先は空欄のまま）＋送付メール本文（`メール/templates/見積送付.md` 準拠）
- **缶バッジ**：回答メール本文（仕様パターンごとの単価表・送料・リードタイム・校正の段取り・有効期限）。必要なら見積書ドラフトも
- 単価欄は次のルールで**「案」として**埋める：
  - 参考価格がある → **案A：前回同額**／**案B：参考値±10%**（理由付き。営業 CLAUDE.md の「初回は幅を持たせる」）
  - 参考価格が無い → **単価は空欄**。「翔さん入力」と書く。数字を発明しない
- 納期は「ご注文確定後 ○営業日」の形。営業日／暦日を必ず明記。参考が無ければ空欄
- すべての数字に `※案` を付ける。合計・税は Bash で計算して検算班に回す

## 4. 検算班 `kensan-han` の検問（省略不可）
- 叩き台と参考価格の一覧を渡し、判定をもらう
- ⚠要修正 → 直して再検問（最大2周）。それでも通らなければ、通らなかった項目を報告に載せて翔さんの判断に回す
- 「出典なしの数字」が1つでもあれば、その数字は**空欄に戻す**

## 5. 翔さんへの報告（1画面。ここで一旦止まる）
```
## ○○社 見積案（YYYY-MM-DD）　回答期限：MM/DD
### 要求仕様
（表。空欄＝先方に確認：N件）
### 参考価格（出典付き）
- 前回 YYYY-MM-DD：…（メール件名）
### 単価案
| 案 | 単価 | 理由 |
| A | … | 前回同額（継続重視）|
| B | … | 参考±10%（理由）|
| C | 翔さん入力 | |
### 納期案：…（営業日）
### 検問結果：✅通過 ／ ⚠…（未解決）
### 先方に確認すること：…
→ **「A」「B」「単価 xxx で」のどれかを返してください。返事の後に見積書と Gmail 下書きを確定します。**
```
- 推奨は1つ明示する（me.md）。ただし決めない・急かさない
- 5行で足りるなら5行でいい

## 6. 翔さんの返事のあと（確定フェーズ）
1. 選ばれた単価・納期で叩き台を確定。`※案` を外す
2. 保存：鉄鋼 → `鉄鋼事業部/営業/見積書/[顧客名]_[YYYYMMDD]_draft.md`／缶バッジ → `缶バッジ事業部/営業/見積/[顧客名]_[YYYYMMDD]_[案件]_draft.md`（無ければ作る）
3. **確定版でもう一度 検算班**（数字の転記ミス防止）→ 通過後に Gmail 下書きを作成（起案班の create_draft。**送信はしない**）。件名は既存スレッドの件名に「Re:」、新規なら「御見積書のご送付について（三幸商事）」
4. `context/decision_log.md` に1行（例：`| YYYY-MM-DD | 缶バッジ | ○○社 △△ 単価は前回同額で回答 | リピート・関係継続優先 | +10% 提示 |`）
5. 未確認事項が残っていれば、メール本文に「下記ご確認ください」として先方への質問を入れる
6. 報告は3行：「Gmail 下書き作成（件名）／見積書 <path>／送信は翔さんで」
7. `context/ops_log.md` に1行 append、コミット＆push

## やらないこと
- 単価・納期を Claude が確定する／翔さんの返事なしに Gmail 下書きを作る
- 参考価格が無いのに数字を置く（空欄が正解）
- 仕入価格・原価・粗利・スポット推奨・他社の値段の噂を社外文書に書く
- 検算班を飛ばす（急ぎでも飛ばさない。急ぎは「報告を短くする」で対応する）
- 送信

## 例
- 「キャラバンの缶ミラー26種の見積」→ Gmail で市川氏スレッド → 要求仕様（φ76mm・520／1,040枚・3仕様）→ Asana で過去の缶ミラー案件の単価 → 起案班：仕様×数量の単価表（案A/B）＋送料＋リードタイム → 検算班 → 翔さんに1画面 → 「A」→ 確定・下書き・decision_log
- 「サンワの納期返信」→ 見積は既出、納期だけ → 要求仕様は納期欄中心 → 参考：前回リードタイム → 検算班 → 「ご注文確定後 ○営業日」案を提示 → OK 後に下書き
