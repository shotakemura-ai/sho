# /kikaku — 企画設計の手順（判断・壁打ち系②）

らすく式「新しい企画や仕組みを作るときは、まず設計から入る」の実装。
翔さんは着想（TOP5）で構想が湧く。落とし穴は「完璧主義で出すのが遅れる」「動いているものを触りたくなる」（strengths.md）。
だからこのスキルは **設計シート1枚を60点で速く出す → 翔さんが判断項目だけ埋める → 最小実験で確かめる** に固定する。

## 0. 準備（黙ってやる）
1. `TZ=Asia/Tokyo date '+%Y-%m-%d'`。仕事（鉄鋼／缶バッジ）か個人かを判定
2. **同じ企画を過去に扱っていないか**を先に調べる（重複設計・捨てた案の蒸し返しを防ぐ）
   - `context/business_os.md` §5「やりたいこと（構想の在庫）」と §6「やらないと決めたこと」
   - `context/decision_log.md` を企画名・キーワードで grep（**捨てた案なら最初にそう言う**。「それは〇月〇日に見送った案」）
   - `C:\Users\FONE\.claude\projects\C--Users-FONE\memory\MEMORY.md` の索引から該当ファイルだけ開く
   - Asana に関連タスクがあれば期限・状態を1行
3. 材料が足りない項目は聞かずに「未定」「仮」で置いて進める（白紙脱出）。聞くのは企画の対象が特定できない時だけ・1問

## 1. 設計シート（A4 1枚・項目固定・順番固定）
| # | 項目 | 書き方 |
|---|---|---|
| 1 | **一言** | この企画は何か。**誰の何に「役に立つ」か**（提供価値の一文。business_os §4） |
| 2 | 背景・きっかけ | なぜ今か。誰の発案か（社長・顧客・翔さん・AI 提案） |
| 3 | 狙い（数値） | 売上・粗利・件数・トン・期間。**計画原紙／§2 のどの数字に効くか**を明示。置けない数字は「未定」（推測で埋めない） |
| 4 | 対象 | 顧客・利用者。注力3社（FUNBOX・ファングッズ・サンワ）や既存顧客との関係 |
| 5 | 提供価値と Win-Win | 相手のメリット／うちのメリット。片方しか無ければそう書く |
| 6 | やらないこと | §6 との照合結果。スポット・値引きで解決・ロイヤリティ受取・仕入価格の開示などの禁じ手に触れないか |
| 7 | 収支の骨子 | 初期費用・月次費用・回収の仮定。仕入価格・原価は**社内メモ扱い**（社外資料に転記しない） |
| 8 | **最小実験** | 60点で出す最初の1件・1社・1か月。何を確かめるか（成功条件を1つ）。最上志向の補正 |
| 9 | リスクと急所 | 最大3つ。急所＝外すと致命傷になる1点を太字 |
| 10 | 既存との統合 | **増築禁止チェック**：既存の商品・仕組み・Routine・スキルに足せないか。新設が必要なら理由を1行 |
| 11 | **判断項目** | 翔さんにしか決められないことの箇条書き（金額・単価・相手先・時期・人）。ここが埋まればシート完成 |
| 12 | 次の1手 | Asana に入れる粒度で1〜2件（期限つき）。全工程は親タスク＋未割当サブタスクに |

- 複数の形があり得るなら **最大3案＋推奨1つ**（トレードオフ各1行）を項目1の下に置く
- 「今までの延長」の案には必ず「頭を使う版」を並べる（§0 旗印）
- 商談・提案の前なら sbt.md の「ベストシナリオを冒頭に1段落」を添える

## 2. 出力先（保存前に `ls` で確認。無ければ作る）
- 鉄鋼・全社：`経営企画室/プロジェクト/<企画名>/YYYYMMDD_<企画名>_設計シート.md`
- 缶バッジ・三幸プロダクツ：`缶バッジ事業部/` 配下の該当フォルダ（既存があればそこ）
- 個人：`PB/` 配下。三幸商事の顧客情報を混ぜない
- ホーム直下に案件フォルダを新設しない

## 3. 検問（提示前）
- 項目3・7に金額・数量・納期があれば **検算班 `kensan-han`** を通す（Claude Code）。文末に「⚠人間確認必須」
- 一度通読してから出す。「叩き台です」で未完成を渡さない（判断項目が明示された状態が完成形）

## 4. 翔さんの OK 後（設計→制作へ）
| 次にやること | 使うもの |
|---|---|
| 設計をさらに詰める | `/grill-me`（判断項目を1つずつ潰す） |
| 会議資料・提案書にする | `bumon-pres` ／ `design-studio` ／ `kian-han` |
| 図解・画像 | `/codex` |
| 判断に迷う | `/handan`。重ければ `/virtual-board` |
| 記録 | 決定→`decision_log.md`／構想の状態→`business_os.md` §5 を更新／翔さんの宿題→Asana／AI の宿題→`ai_backlog.md` |

## やらないこと
- 設計シートを飛ばして資料・LP・実装から作る
- 数字を推測で埋める（「仮」「未定」を隠さない）
- 12項目を増やす（増やしたくなったら §10 の増築禁止を思い出す）
- 捨てた案（decision_log）を黙って復活させる

## 例
- 翔さん「マシンレンタルの素案、固めたい」（Asana 9/18 期限超過）
  → §5 に「缶バッジマシンのお試しレンタル（社長発案）」あり・memory/kanbadge_machine_rental_scheme を読む → 設計シート：一言「初めての店舗が 80,000円の機械を買う前に試せる」、狙い＝パーツ顧客の増加（数字は仮）、最小実験＝1店舗・1か月、判断項目＝レンタル料・保証金・対象機種・回収時の状態基準 → `経営企画室/プロジェクト/マシンレンタル/YYYYMMDD_マシンレンタル_設計シート.md`
