# /oboete — 指摘をその場でルール化する

らすく式「失敗を毎回ルール化する」の実装。
**聞き返さない。分類して、書いて、1行で報告する。**（承認ミニマリズム：repo 内の追記は「進めていい側」）

## 手順

1. **何を覚えるか決める**
   - 引数があればそれ。無ければ直前の翔さんの発言（指摘・手直し・決定）から抽出
   - 「ルール」の形に言い換える：❌「文字が小さい」→ ✅「補足も本文と同じ文字サイズにする」
   - 1行で言えない場合は、1行にできる粒度まで削る（複数なら複数行にする）

2. **保存先を分類する**（迷ったら preferences.md）

   | 中身 | 保存先 | 形式 |
   |------|--------|------|
   | 文体・言い回し・出力形式・長さ・トーンの好み／NG | `context/preferences.md` | 表に1行 |
   | 作業手順のミス→次から防ぐルール | `context/learnings.md` | 推奨フォーマット（状況/試したこと/結果/学び）。カテゴリ `失敗` |
   | 何かを決めた（選んだ・方針変更・やらない） | `context/decision_log.md` | 表に1行（見送った案も） |
   | 顧客・会社・人に関する事実 | 該当ファイル（`context/customers.md` / `company_profile.md` / `conversation_topics.md`） | そのファイルの形式に合わせる |
   | 特定のスキル／班の動き方への指摘 | そのスキルの `SKILL.md` か `.claude/agents/*.md` の該当箇所 | 既存ルールの末尾に1行追加（**既存行は消さない**） |

   1つの指摘が2か所に当たるなら両方に書く（例：失敗のルール化 → learnings.md に記録 + 該当 SKILL.md に1行）。

3. **重複チェック** — 保存先ファイルを `grep` して、同じ趣旨の行があれば追記せず「すでにあります：〜」と返す。趣旨が更新なら新しい行を追加し、古い行の末尾に `（→ YYYY-MM-DD 更新）` を付ける。既存行の削除はしない。

4. **書く**
   - 日付は必ず `TZ=Asia/Tokyo date '+%Y-%m-%d'`
   - append のみ。`>>` か、表の末尾行の直後に挿入
   - 機密（仕入価格・原価・個人の健康・家計の数字）は書かない。当たったら「これは記録せず、その場限りにします」と返す

5. **同期する** — 端末をまたいで効かせるため、その場でコミット＆push する
   ```bash
   git add <保存先ファイル> && git commit -m "oboete: <ルールを20字以内>" && git push origin $(git branch --show-current)
   ```
   push が失敗しても止まらない（次のセッションで拾う）。

6. **1行で報告する** — 形式固定：
   `覚えました：「<ルール>」→ <保存先ファイル名>`
   複数なら複数行。それ以上の説明はしない。

## やらないこと
- 「これで合ってますか？」と聞き返す（分類ミスは次の指摘で直せばいい）
- me.md / CLAUDE.md を直接書き換える（昇格は R-weekly か翔さんの明示依頼のときだけ）
- ops_log.md への記録（これは作業ログ。/oboete の実行自体は記録しない）

## 例
- 翔さん「メールの締めに『ご検討のほど』は使わんといて」
  → preferences.md：`| 2026-09-24 | 文体 | メールの締めに「ご検討のほど」を使わない | 翔さん指摘 |`
  → 報告：`覚えました：「メールの締めに『ご検討のほど』を使わない」→ preferences.md`
- 翔さん「見積の納期、営業日と暦日を混同してた。次から明記して」
  → learnings.md に `失敗` エントリ + 該当スキルがあれば「納期は『営業日/暦日』を必ず明記」を1行追加
- 翔さん「キャラバンの件、今回はリピート価格で据え置きでいく」
  → decision_log.md に1行（見送った案：値上げ提示）
