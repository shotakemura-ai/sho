# /shodan-ato — 商談後キット（らすく式「面談後レポート」+「AI メンター」の鉄鋼商社版）

翔さんは商談に集中して、終わったら「○○社終わった」と言うだけ。
**その日のうちに**議事録とフォローが出て、宿題が Asana に並ぶ状態を作る。

## 0. 準備
1. `TZ=Asia/Tokyo date '+%Y-%m-%d (%a)'` で今日を確定
2. context/me.md・context/preferences.md・context/email_context.md を読む
3. **文字起こしを手に入れる（上から順に試し、取れた時点で止める。作らない）**
   1. 引数・直前のメッセージに貼られたテキスト
   2. Plaud の MCP ツール（`mcp__plaud*` 等）がこのセッションにあれば、会社名・日付で検索して文字起こしを取得
   3. Zoom for Claude：`zoom_my_notes`（対面録音のノートも入る）と `zoom_meeting` を会社名・当日で検索。ノートは `my_notes_get_note_content` を `include=transcript` で開く
   4. 会社 Windows で動いているなら `context/plaud.md` の NAS パス（該当日の *.md）
   5. どれも無ければ「文字起こしを貼ってください（Plaud アプリ → 共有 → テキスト）」と**1回だけ**言って止まる。**要約や議事録を想像で書かない**
4. 相手先・日時・出席者を、文字起こし＋カレンダーから確定。事前キット（`*_事前キット.md`）があれば読み、「ゴールは達成できたか」の対比に使う

## 1. 作るもの（5点。A〜C は必ず、D・E は材料があれば）

### A. 議事録 → 保存
- 形式：`総務・人事部/議事録/templates/議事録_テンプレート.md` に従う
- 保存先：鉄鋼なら `鉄鋼事業部/営業/商談メモ/YYYYMMDD_<会社名>_議事録.md`、缶バッジなら `缶バッジ事業部/営業/商談メモ/`
- 中身の鉄則：
  - **決定事項／宿題（誰が・いつまで）／保留・持ち帰り** を必ず分ける
  - 数字（単価・数量・納期・金額）が出た箇所は**原文の言い回しのまま引用**し、末尾に「⚠要確認」。丸めない・換算しない
  - 聞き取れない箇所は「（不明瞭）」。埋めない
  - 相手の健康・家族・私的な話は議事録に**書かない**（会話ネタとして conversation_topics に1行残すのは可）

### B. フォローメール下書き → Gmail 下書き（送信しない）
- 起案班 `kian-han` に Agent で委託。渡すもの：議事録の「決定・宿題・保留」＋相手先の宛名＋ email_context.md の型
- 型：お礼1行 → 当日の確認事項の復唱（箇条書き3つ以内）→ こちらの宿題と期日 → 次のアクション → 署名
- **金額・数量・納期が本文に入るなら、下書き作成の前に検算班 `kensan-han` を通す**。通過するまで Gmail 下書きを作らない
- 件名は「【御礼】本日の打ち合わせについて（三幸商事 竹村）」を基本に、相手の文化に合わせる
- 出来たら「Gmail の下書きに入れました。送信は翔さんが」と報告

### C. Asana 登録案（提案のみ）
- 宿題ごとに `タスク名／担当／期日／プロジェクト（既存があればそれ）` を表で出す
- **翔さんが「OK」「1と3だけ」と返してから** create。返事が無ければ作らない（Asana の書き込みは確認が要る設定）
- 相手側の宿題は「○○社：△△（期日）」として翔さん担当の「確認」タスクにする

### D. 翔さんへの振り返り（AI メンター。5行以内・任意）
- 文字起こしが会話の実録であるときだけ（要約しか無い時は書かない）
- 「良かった進行 2つ」「次回こう変える 1つ」。根拠は文字起こしの該当箇所を短く引く
- トーンは context/sbt.md（プラスの言葉・成功イメージ）。採点・説教・罪悪感は禁止。me.md「判断を急かさない」を守る

### E. 育てる（材料があるときだけ・すべて提案止まり）
- `context/customers.md`：担当者名・部署・役職・連絡先・取引内容が新しく分かったら追記案を出す（OK で追記）
- `context/decision_log.md`：翔さんが商談中に**決めた**こと（受ける・断る・条件を変える）があれば行案を出す（OK で追記）
- `context/conversation_topics.md`：相手の出身・趣味・共通の知人など次回に効く1行があれば追記案

## 2. 報告（1画面）
```
## ○○社 商談後キット（YYYY-MM-DD）
- 決定：…／…
- 宿題：うち→…（期日）／先方→…（期日）
- 保留：…
- ⚠数字の出た箇所：N件（議事録に原文ママ・要確認）
- 出来たもの：議事録 <path>／Gmail 下書き（件名）
- OK 待ち：Asana 登録案 N件／customers.md 追記 N件／decision_log N件  ← 「OK」「1と2だけ」で反映
（任意）振り返り：良かった…／次回…
```

## 3. 後処理
- `context/ops_log.md` に1行 append
- コミット＆push（現在のブランチ）。失敗しても止まらない
- 翔さんの OK が来たら C・E を反映し、「反映しました：Asana 2件・customers 1件」と1行

## やらないこと
- メール送信、Asana の勝手な作成・更新、カレンダー変更
- 文字起こしが無い状態での議事録作成（クリティカル7「重要顧客への一次対応」に直結するため）
- 仕入価格・原価をフォローメールに書く（議事録＝社内文書には残してよいが、メールには絶対に載せない）
