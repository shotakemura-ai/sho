## 毎日任せている仕事（らすく式「実例7つ」→ 竹村版パイプライン）
翔さんがやるのは**テーマ決め・推敲・最終確認（送信／公開／登録）**だけ。AI は下の鎖を勝手に通す。

| # | らすく | 竹村版 | 鎖（スキルの順） | 翔さんの手 |
|---|---|---|---|---|
| ① | 記事づくりの一気通貫 | 出張報告書・会議まとめ・badge-koi 記事・顧客向け資料 | `/kiji` →（図解 `/codex`）→ 入稿形式（design-studio 道B／docx）→ 告知文 | 素材を渡す・推敲・公開 |
| ② | AI メンターとの高速 PDCA | 商談・会議進行・プレゼン・1on1 の採点 FB | Plaud 録音 → `/mentor`（採点・次回の一手）→ 次回の `/shodan-mae` 冒頭に再掲 → 3回続く指摘は `/oboete` | 「採点して」と言う |
| ③ | つぶやきの共作 | バッジこい!! の X・Instagram | design-studio（ネタ→候補→本文→図解 `/codex`）→ 翔さんが選んで投稿 | 選ぶ・自分の言葉を足す・投稿 |
| ④ | クライアント対応の裏方 | 商談・訪問・会食の前後 | `/shodan-mae`（事前キット）→ 商談 → `/shodan-ato`（議事録・フォロー下書き・Asana 案・顧客マスター） | 商談に集中・送信 OK |
| ⑤ | ポートフォリオサイトの改修 | badge-koi サイト・EC ページ・社内ツールの改修 | 設計は Claude → 実装は `/codex` → Claude が検品 → 公開は翔さん（design-studio の禁則に従う） | 直したい点を言う・公開 |
| ⑥ | オフ会運営 | 展示会出展・工場見学・顧客向けセミナー・社内会議 | `/kikaku`（設計シート）→ design-studio（告知・バナー）→ `bumon-pres`（当日資料・進行台本）→ 事後：アンケート集計＋`/mentor` | 企画の判断項目・当日 |
| ⑦ | 失敗を毎回ルール化 | 指摘・手直し・決定の即記録 | `/oboete` → preferences.md／learnings.md／該当 SKILL.md → R-weekly が3回以上のものを me.md・AGENTS.md へ昇格提案 | 一言「次から〜して」 |

寝ている間の自動運転（定期実行）は `経営企画室/AI運用台帳.md` §1 と `context/routines/README.md`。月次は R-monthly（1日 9:00）→ 朝刊 → `/getsuji`、家計は kakei-monthly（1日 7:00）。

## つながり（どのスキルがどのスキルを呼ぶか）
- 文章を作るスキル（mail-ops・kian-han・design-studio・shodan-ato・mitsumori・kiji）→ 書く前に `/buntai`
- `/kikaku` の設計シートが OK → 詰めるなら `grill-me`、資料は `bumon-pres`／`design-studio`、図解は `/codex`、迷ったら `/handan`
- `/handan` で「重い」と判定 → `virtual-board`
- `/getsuji` の「来月の重点3つ」→ 月初の朝刊（R-daily）が再掲
- `/shodan-ato` の振り返りを深掘り → `/mentor`。`/mentor` の「次回の一手」→ 次回の `/shodan-mae`
- どのスキルでも翔さんの指摘が出たら `/oboete`

## 運用ルール
- スキルは「繰り返す仕事」を1つずつ言葉にしたもの。**新設は既存が2週間使われてから**（増築禁止。2026-09-25〜26 の6本は本人指示による例外）
- スキルの手順にミスがあったら、その場で `/oboete` → 該当 SKILL.md に1行足す（失敗をルール化）
- 送信・Asana 書き込み・カレンダー変更・公開は、どのスキルも翔さんの OK 後
- 2週間使われなかったスキルは R-weekly が「捨てる／統合する」候補に挙げる
