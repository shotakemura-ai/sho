# /getsuji — 月次の壁打ち進行役（判断・壁打ち系③）

らすく式「毎月の振り返りセッションの進行役」の実装。R-weekly（週次・自動・AI が書く）の上に乗る**月1回・対話型**の層。
原則は v3 と同じ：**事実は AI が集める。翔さんは問いに答えるだけ。記録は AI が書く。罪悪感 KPI は持ち込まない。**
所要 30分。翔さんの返答は1行でいい。

## 0. 準備（黙ってやる）
1. `TZ=Asia/Tokyo date '+%Y-%m-%d (%a)'`。対象月を確定（引数が無ければ今月。月初1〜7日の起動なら前月を対象にする）
2. 前回の壁打ちファイル `経営企画室/レポート/月次壁打ち/YYYYMM.md`（前月分）があれば読む。無ければ「初回」として進める
3. **対象月の `YYYYMM_事実.md`**（クラウド Routine R-monthly が毎月1日 09:00 に自動生成。正本 `context/routines/monthly-review.md`）があれば、下の「1. 事実」の集計はスキップしてそれを読み、Asana の未完了・期限超過だけ追加で取って Q1 から始める。無ければ自分で集計する

## 1. 事実（AI がやる。実データのみ・推測で数字を作らない）
| 何を | どこから | 出し方 |
|---|---|---|
| 週次振り返り | `context/learnings.md` の対象月分（R-weekly が書いた「週次振り返り」見出し） | 各週の「事実」と「今週の問い」の答えを1行ずつ |
| 決めたこと | `context/decision_log.md` 対象月の行 | 件数と、方針レベルのものを箇条書き |
| AI に任せたこと | `context/ops_log.md` 対象月の行 | 件数・領域内訳（鉄鋼／缶バッジ／個人／仕組み） |
| AI の宿題 | `context/ai_backlog.md` | 完了・進行中・期限超過の件数。超過分は列挙 |
| 翔さんのタスク | Asana マイタスク（`search_tasks_preview` assignee=me・未完了） | 期限超過の件数と上位3件 |
| 朝刊 | `daily/` の対象月ファイル数、提案の採用形跡 | 数字だけ |
| 前月の重点3つ | 前回の壁打ちファイル | 各「できた／途中／手つかず」の判定材料（decision_log・ops_log・Asana から） |
| 計画原紙に対する現在地 | `経営企画室/レポート/月次経営ダッシュボード_*.html` や部門損益レビューが対象月分あればそこから。**無ければ数字は翔さんに聞く**（作らない） | 売上・粗利・粗利率・トンの対計画 |

まとめは A4 半分。**プラス材料から始める**（sbt.md）。未達は事実として1行、責めない。

## 2. 進行（問いは1つずつ・最大5問・各問いに AI の推奨回答を添える）
grill-me 流：一度に1問。翔さんが「OK」「違う」「2」で答えられる形にする。
1. **Q1 前月の重点3つ、実際どうだった？** — AI の判定（できた／途中／手つかず）を先に示し、翔さんは訂正だけ
2. **Q2 一番効いた一手と、一番のムダは？** — AI が候補を各1つ挙げる（ops_log・decision_log から）
3. **Q3 計画原紙に対する現在地は？** — 数字が repo に無ければここで翔さんからもらう。もらった数字はそのまま記録（換算・推定しない）
4. **Q4 来月の重点3つは？** — AI が候補を3〜5つ、事実から根拠つきで提示（改善系・選択肢系・関係深耕系のバランス。strengths.md）。翔さんが番号で選ぶ。「頭を使う版」を1つは混ぜる（business_os §0）
5. **Q5 AI に任せることを1つ増やす／減らすなら？** — 任せて楽になったこと・ならなかったことを事実から1つずつ

- 大目標への接続を1行：89期は計画原紙の必達（§2）、個人は純資産 5,000万円／50歳（§8）。「近づいた実感」を数字で1行（sbt.md-4）
- 翔さんが疲れていれば Q4 だけで終えてよい（重点3つが決まれば月次は成立）

## 3. 出力：`経営企画室/レポート/月次壁打ち/YYYYMM.md`（保存前に `ls`。フォルダが無ければ作る）
```
# 月次壁打ち YYYY年MM月（YYYY-MM-DD 実施）
## 事実（AI 集計）
## 問答（Q1〜Q5・翔さんの答えをそのまま）
## 来月の重点3つ
1. 〇〇 — 根拠1行 — 最初の1手
2. …
3. …
## 宿題
- 翔さん → Asana に登録済み：…
- AI → ai_backlog に登録済み：…
## 決めたこと → decision_log に転記済み：…
```

## 4. 事後（記録は AI の仕事・その場でやる）
- 翔さんの宿題 → Asana マイタスク（期限必須・次の1手だけ・AI の存在を出さない）。AI の宿題 → `context/ai_backlog.md`
- 決めたこと → `context/decision_log.md`。方針レベルなら `context/business_os.md`（§2 数値・§3 戦略の軸・§5 構想の状態）
- 翔さんの指摘（「この問い要らん」等）→ `/oboete` → preferences.md か、このファイルの該当行に1行追記（既存行は消さない）
- 朝刊への反映：**月初〜7日の R-daily が最新の壁打ちファイルの「来月の重点3つ」を冒頭に再掲する**（`context/routines/daily-agent.md` に反映済みか確認。未反映なら ai_backlog の該当行に沿って進める）
- `context/ops_log.md` に1行 append

## やらないこと
- 数字を推測で作る・換算する（翔さんの数字はそのまま）
- 問いを6つ以上にする。説教・詰問・「先月も同じことを言った」
- 仕組みの増築を提案する（改善提案は「既存を変える」に限る。R-weekly と同じ）
- 重点を4つ以上にする（3つに絞れないなら翔さんに削ってもらう）

## 例
- 翔さん「月次やろう」（10月2日）
  → 対象は9月。learnings.md の9月の週次4本・decision_log 9月（例：計画原紙必達・注力3社・マンダラ捨て）・ops_log 9月・Asana 超過を集計 → 「9月はプラス材料から：事業OSが埋まった／決定〇件。未達：Asana 超過〇件」→ Q1〜Q5 → 重点3つ → `月次壁打ち/202609.md` → 宿題登録 → 10月の朝刊で再掲
